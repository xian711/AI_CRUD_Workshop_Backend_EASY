# LESSONS（錯誤防範庫）

記錄實際踩過的坑，格式固定三段：**問題 → 原因 → 防範**。

回填時機（事件表——loop 結尾**逐項對照**，中了就記；機械對照，不靠自由心證）：

- E1 同一問題 fix 兩輪才修好。
- E2 Review 出現 ❌ 且已修正。
- E3 使用者人工指正 AI 的產出。
- E4 驗證曾失敗（含環境／工具坑；一輪就修好也記，記原因不記過程）。
- E5 選擇題建議項被使用者否決（記 AI 建議什麼、人選什麼、差在哪）。

使用規則：

- 新 loop 開始時先掃本檔，套用相關防範規則。
- 一行一坑，不寫長文。
- 防範規則若已成通則，升級進 `HARNESS.md` 或對應模組，本檔留出處紀錄。升級前必答「最便宜等效替代」：一句話能防的不寫成一段、一段能防的不開新檔；說不出為何更便宜的寫法不夠，就不升級（防規則庫膨脹吃掉 token 預算）。

| ID | 問題 | 原因 | 防範 |
|---|---|---|---|
| LS-01 | 分頁元件顯示「第 NaN 頁」 | API 回應前 props 是 undefined | 分頁 props 一律給預設值（`?? 1`、`?? 0`） |
| LS-02 | E2E 計數斷言永遠是 0 | 計數類 API 是即時快照、不自動等待 | 計數前先等待目標元素條件成立 |
| LS-03 | E2E 測試燒掉真實 AI 額度 | 直接打外部付費 API | 外部 API 一律 route 攔截 mock，回應照真實格式 |
| LS-04 | 測失敗路徑時誤報 console error | 刻意觸發的 500 也被斷言抓到 | 「無 console error」斷言要排除刻意觸發的錯誤 |
| LS-05 | 複製相似頁面後路徑沒改 | layout / 路由從別的角色頁複製 | 複製頁面後逐一確認 layout 與導覽路徑 |
| LS-06 | 改共用元件弄破別的頁面 | 沒先盤點使用方 | 改共用元件 / token 前先 grep 所有使用方，列回歸清單 |
| LS-07 | PowerShell 跑 curl 指令參數全錯 | `curl` 在 PowerShell 是 `Invoke-WebRequest` 別名 | smoke 測試一律明寫 `curl.exe` |
| LS-08 | 改既有檔案時悄悄刪掉原始碼 | 編輯範圍過大、整段覆寫 | commit 前跑 `git diff -- <檔案>` 逐行看被刪的行（10 秒），非預期刪除即還原 |
| LS-09 | 新寫的 `.ps1` 一跑就 parse error、中文全亂碼 | 無 BOM 的 UTF-8 被 PowerShell 5.1 以 ANSI 解碼 | 含中文的 `.ps1` 一律存成 UTF-8 with BOM |
