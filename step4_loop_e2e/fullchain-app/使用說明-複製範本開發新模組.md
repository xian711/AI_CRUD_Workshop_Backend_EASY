## 0. 前置準備

### 0.1 啟動 dev server

```bash
cd frontend
pnpm install          # 首次或相依有變動時
pnpm dev              # nuxt dev，預設 port 3000
```

啟動後開瀏覽器到 <http://localhost:3000/template/crud>。

> 埠號來自 `frontend/nuxt.config.ts`（`devServer.port: 3000`）。若 3000 被占用，Nuxt 會自動跳到 3001，注意終端機印出的實際網址。

**檢查點 ✅**：你應該看到一個人員清單頁 —— 上方篩選卡（關鍵字／編組／狀態／進階／清除）、一張桌機表格、右上「匯出 CSV」、麵包屑右側有「新增人員」按鈕。

### 0.2 先玩過一輪範本

動手複製之前，先把範本當使用者操作一遍，建立心智模型：

1. 在關鍵字打「陳」→ 表格即時過濾。
2. 點「進階」→ 展開資格／居住縣市／鄉鎮區；選一個縣市，注意鄉鎮區下拉會**相依載入**。
3. 點表頭「更新日期」排序 → 看網址列 query 變化（`?sort=updatedAt:desc`）。
4. 複製當前網址、開新分頁貼上 → 篩選與排序**完整還原**（URL 狀態同步）。
5. 點一列進檢視頁 → 右上「編輯」→ 清空姓名按「儲存」→ 欄位下方出現**紅字錯誤**、自動聚焦第一個錯誤欄位（不是只有 toast）。
6. 回列表 → 點某列的垃圾桶 → 二次確認 modal → 刪除。
7. 縮視窗到手機寬度（< 768px）→ 表格變成卡片清單。

**檢查點 ✅**：以上七步都能重現。這七個行為就是你複製出來的新模組會「免費繼承」的能力。

## 1. 心法：複製 vs 共用

範本共 8 個檔，分兩類。**決定哪些複製、哪些共用，是整件事的核心。**

| 檔案 | 動作 | 為什麼 |
|------|:---:|------|
| `pages/template/crud/index.vue` | **複製改名** | 綁定「這個實體」的欄位、篩選、表格欄位 |
| `pages/template/crud/[id].vue` | **複製改名** | 綁定「這個實體」的表單區塊、驗證規則 |
| `composables/useTemplateMembers.ts` | **複製改名** | 綁定「這個實體」的型別、種子、CRUD |
| `components/template/TemplateFormField.vue` | **複製改名** | 命名空間隔離，避免與別的模組互相污染 |
| `components/template/TemplateStatusBadge.vue` | **複製改名** | 狀態列舉是實體特有的 |
| `composables/useTemplateListPage.ts` | **直接共用** | 通用列表狀態工廠，與實體無關 |
| `utils/templateValidation.ts` | **直接共用** | 純函式驗證引擎，與實體無關 |
| `utils/templateCsv.ts` | **直接共用** | 純函式 CSV 匯出，與實體無關 |

### 決策準則（背下來）

> **與「這個實體長什麼樣子」有關 → 複製；與實體無關的通用機制 → 共用。**

- `useTemplateListPage` / `templateValidation` / `templateCsv` 三個檔**沒有任何一行提到「人員」**，它們吃泛型或參數。你的新模組直接 `import` 它們即可，不要複製。
- 反過來，`useTemplateMembers` 通篇是「人員」的型別與資料，一定要複製改名。
- 兩個 `Template*` 元件雖然內容通用，但**刻意隔離命名空間**——複製成 `Visit*` 可避免「A 模組改了共用元件、B 模組畫面壞掉」的連鎖，代價只是多兩個小檔（各 < 45 行）。這是刻意的取捨。

> ⚠️ **共用檔的抽象邊界**：`useTemplateListPage` 檔頭（第 8–11 行）明白寫著「**僅支援純字串型 filter**」。如果你的新模組需要布林、多值、或數值區間篩選，**請複製這個檔再擴充**，不要硬套。這條界線是誠實標注的，不是 bug。

## 2. 完整步驟：把 template/crud 變成 visit-records

情境：我們要做「訪視紀錄」模組，記錄社工訪視個案的紀錄。實體叫 `VisitRecord`。

### 改名對照表（全域）

| 範本 | 新模組 | 出現位置 |
|------|--------|---------|
| `template/crud`（路徑） | `visit-records` | 頁面資料夾、`router.push` 路徑 |
| `Template`（型別/元件前綴） | `Visit` | 型別、元件名、常數 |
| `template`（檔名前綴） | `visit`（或 `visitRecords`） | composable / util 檔名 |
| `TemplateMember` | `VisitRecord` | 主型別 |
| `useTemplateMembers` | `useVisitRecords` | 資料層 composable |
| 人員（UI 文字） | 訪視紀錄 | 標題、toast、按鈕文字 |

### 步驟 1 — 複製檔案並改名

```bash
cd frontend

# 頁面（複製整個資料夾）
mkdir -p pages/visit-records
cp pages/template/crud/index.vue      pages/visit-records/index.vue
cp "pages/template/crud/[id].vue"     "pages/visit-records/[id].vue"

# 資料層（只複製要客製的）
cp composables/useTemplateMembers.ts  composables/useVisitRecords.ts

# 元件（命名空間隔離）
mkdir -p components/visit
cp components/template/TemplateFormField.vue   components/visit/VisitFormField.vue
cp components/template/TemplateStatusBadge.vue components/visit/VisitStatusBadge.vue

# ── 這三個「共用」，不複製 ──
# composables/useTemplateListPage.ts
# utils/templateValidation.ts
# utils/templateCsv.ts
```

> Nuxt 的元件前綴去重規則：`components/visit/VisitFormField.vue` 的使用名就是 `<VisitFormField>`（先例：`components/plan/PlanXxx.vue`）。放進 `visit/` 子資料夾即可。

**檢查點 ✅**：`ls pages/visit-records/` 有 `index.vue` 與 `[id].vue`；`ls components/visit/` 有兩個 `Visit*.vue`。此時 dev server 應仍能編譯（雖然新頁面內容還是「人員」）。開 <http://localhost:3000/visit-records> 應能看到與範本一樣的畫面。

### 步驟 2 — 改資料模型（`useVisitRecords.ts`）

這是改動量最大的一步。打開 `composables/useVisitRecords.ts`，依序改四塊。

**(a) 型別與列舉常數**（原檔第 18–57 行）

把「人員」的欄位換成「訪視紀錄」的欄位。範例：

```ts
export type VisitStatus = '待訪視' | '已完成' | '已取消'
export type VisitMethod = '家訪' | '電訪' | '視訊'

export interface VisitRecord {
  id: string                 // 'V-001'
  caseName: string           // 個案姓名（一般文字）
  visitDate: string          // YYYY-MM-DD（日期）
  method: VisitMethod        // 訪視方式（enum → select）
  visitorName: string        // 訪視員
  county: string             // 相依下拉（縣市→鄉鎮區）
  township: string
  address: string
  tags: string[]             // 多值標籤
  status: VisitStatus        // 狀態 badge
  summary: string            // 長文字
  updatedAt: string          // 系統寫入
}

export type VisitRecordInput = Omit<VisitRecord, 'id' | 'updatedAt'>

export const VISIT_STATUS_OPTIONS: VisitStatus[] = ['待訪視', '已完成', '已取消']
export const VISIT_METHOD_OPTIONS: VisitMethod[] = ['家訪', '電訪', '視訊']
export const VISIT_TAG_OPTIONS = ['獨居', '低收', '身障', '高風險']
```

> **保留 `TEMPLATE_POSITION_META` 這種「查表」模式的精神**：若你的實體也有「代碼 → 顯示名 + 排序權重」的欄位（範本用它處理職務），照抄那張 `Record<Code, { title; weight }>` 對照表與 `xxxTitleOf` / `xxxWeightOf` 兩個導出函式。沒有這種欄位就整段刪掉。

**(b) 種子資料**（原檔第 72–97 行）

把 24 筆人員字面量換成你的實體資料。**維持「顯性字面量」寫法，不要改成 hash 產生器**：

```ts
const SEED: Omit<VisitRecord, 'id'>[] = [
  { caseName: '王小明', visitDate: '2026-07-01', method: '家訪', visitorName: '社工A',
    county: '臺東縣', township: '臺東市', address: '中華路一段120號',
    tags: ['獨居', '低收'], status: '已完成', summary: '個案狀況穩定',
    updatedAt: '2026-07-05' },
  // …再補 23 筆，涵蓋所有 status / method / tag 組合，分頁預設 10 筆恰好 3 頁
]
```

> 種子資料要求（比照範本）：涵蓋所有列舉組合、至少數筆各種狀態、集中在少數縣市 2~4 個鄉鎮以便示範相依下拉、`updatedAt` 分佈於數個月以便示範排序、**檔頭註解標明是虛構測試資料**。

**(c) 流水 id 與 CRUD**（原檔第 100–170 行）

- `ensureSeeded()`：把 id 前綴從 `M-` 改成 `V-`（第 105 行）。
- `nextId()`：把 `member.id.replace('M-', '')` 改成 `replace('V-', '')`（第 129 行）。
- 5 個 API（`records` / `getById` / `create` / `update` / `remove`）內部把 `member` 改成 `record`、把型別換掉即可，**簽章與非同步結構完全不動**（後端接軌預告見第 5 節）。
- `todayString()`（第 113–119 行）與 `cloneMember()`（改名 `cloneRecord`，第 122–124 行）**照抄**。`todayString()` 用本地時區組 `YYYY-MM-DD`，**絕不能改成 `toISOString()`**（原因見第 4 節 FAQ）。

**檢查點 ✅**：TypeScript 不報錯（`useVisitRecords.ts` 自成一格，此時頁面還沒改，會因型別不符報錯——這是預期的，下一步就修）。

### 步驟 3 — 改列表頁（`visit-records/index.vue`）

打開 `pages/visit-records/index.vue`，對照原檔行號逐塊改：

**(a) import 與 `definePageMeta`**（原檔第 226–241 行）
- import 來源全部指向新檔：`useVisitRecords`、`VISIT_*` 常數、型別。
- `useTemplateListPage`、`useTableSort`、`exportCsv`、`taiwanAddress` **維持共用 import 不動**。
- `definePageMeta({ layout: 'township', pageTitle: '訪視紀錄管理' })`。

**(b) 篩選欄位**（原檔第 258–290 行）
這是「換篩選欄位」的重點區。`useTemplateListPage` 的 `defaultFilters` 決定有哪些篩選：

```ts
const { filters, page, pageSize, showAdvanced, resetFilters, advancedActiveCount, buildReturnQuery } =
  useTemplateListPage({
    defaultFilters: { q: '', method: ALL, status: ALL, tag: ALL, county: ALL, township: ALL },
    advancedKeys: ['tag', 'county', 'township'],   // 這幾個算「進階」，只有它們計入徽章數
  })
```

- 每個 key 對應一個下拉；`advancedKeys` 列出「摺在進階區」的欄位（FR-T-102 的徽章只數這些）。
- 下拉選項一律 `[ALL, ...實值]`（`ALL = '全部'` 哨兵，原檔第 248 行）。**不要用空字串當「全部」**（原因見 FAQ）。
- 縣市→鄉鎮區相依下拉（原檔第 272–290 行）**照抄**，只改變數名。

**(c) 過濾邏輯 `matchesFilters`**（原檔第 336–348 行）
每個篩選條件一個 early return，改成你的欄位：

```ts
function matchesFilters(record: VisitRecord): boolean {
  const keyword = filters.q.trim().toLowerCase()
  if (keyword && !`${record.caseName} ${record.visitorName}`.toLowerCase().includes(keyword)) return false
  if (filters.method !== ALL && record.method !== filters.method) return false
  if (filters.status !== ALL && record.status !== filters.status) return false
  if (filters.tag !== ALL && !record.tags.includes(filters.tag)) return false
  if (filters.county !== ALL && record.county !== filters.county) return false
  if (filters.township !== ALL && record.township !== filters.township) return false
  return true
}
```

**(d) 排序欄位**（原檔第 293–309 行）
`sortableColumns` 列出可點表頭排序的欄位；`defaultSortRules` 是預設排序；有需要數值排序的欄位（如範本的職務權重）才給 `accessors`。

**(e) 表格與手機卡片欄位**（template 區，原檔第 106–191 行）
把 `<th>`／`<td>`／卡片內的欄位換成你的欄位；`TemplateStatusBadge` 改 `VisitStatusBadge`；記得**桌機與手機的顯示資訊要等價**（NFR-T-01）。

**(f) CSV 欄位**（原檔第 405–426 行）
`handleExport()` 內的 `columns` 陣列改成你的欄位（`{ label, value: row => ... }`）。`exportCsv` 本身不動。

**檢查點 ✅**：<http://localhost:3000/visit-records> 顯示訪視紀錄清單，篩選、排序、分頁、匯出都能動，導覽點列會跳到 `/visit-records/xxx`（下一步修明細頁）。

## 3. 常見錯誤 FAQ

### Q1. 我把 `<Teleport>` 的 `v-if="teleportReady"` 拿掉了，好像也沒事？

**不要拿掉。** hard-load（直接開網址或按 F5）時，`#breadcrumb-actions` 這個 Teleport 目標在整棵元件樹插入文件前**還不存在**，裸 `<Teleport>` 會產生壞掉的 vnode。因為 `app.vue` 以 `fullPath` 為 key，之後 query 一變會整頁 remount，unmount 那個壞 vnode 時就崩潰。`teleportReady` 在 `onMounted` 後才設 true（`index.vue` 第 244–245 行、`[id].vue` 第 300–301 行），把 Teleport 延後到目標一定存在時才掛載。SPA 內部導覽看不出問題，**只有 hard-load 會爆**——所以很容易漏。

### Q2. 生日／日期欄為什麼用原生 `UInput type="date"`，不用 AppDatePicker？

專案的 `AppDatePicker` 內層包的是 v-calendar **3.1.2**，與 **Vue 3.5 不相容**：選取日期關閉 popover 時會拋 unmount 錯誤，**整頁崩潰**。這是既有相依套件缺陷（全站只剩 2 個舊頁還在用它）。原生 date input 的 `v-model` 本來就是 `YYYY-MM-DD` 字串，與資料模型一致，且鍵盤／行動裝置支援更好。詳見 `[id].vue` 第 133–145 行的長註解。

### Q3. 「全部」可以改成空字串 `''` 嗎？

**不要。** 專案既有慣例是用 `'全部'` 字面哨兵（`index.vue` 第 248 行 `const ALL = '全部'`），所有下拉 options 是 `[ALL, ...實值]` 純字串陣列，過濾時判斷 `value !== ALL` 才生效。空字串會和「關鍵字未填」等其他語意混淆，也和 `useTemplateListPage` 的「只寫入非預設值」邏輯打架。關鍵字 `q` 例外，它的預設值本來就是 `''`。

### Q4. `useTemplateListPage` 裡的 `onScopeDispose` 清理可以省嗎？

**絕對不能。** 這個 composable 用 `setTimeout` 做 URL 同步的 debounce（第 118–122 行）。如果使用者在 300ms 內導航離開列表頁，尚未觸發的 timer 會在**新頁面**上跑 `router.replace`，把列表的 query（篩選、頁碼）污染到明細頁網址。`onScopeDispose`（第 124–126 行）在元件卸載時取消 timer，`writeQuery` 內另有「路由已離開列表頁就不寫」的路徑守衛（第 104 行）作雙保險。這是本範本開發時**雙 reviewer 交集抓到的唯一必修 bug**，靜態看畫面永遠發現不了。凡是 composable 內有 `setTimeout` / `setInterval` / `debounce`，都必須配 `onScopeDispose` 清理。

### Q5. 相依下拉（縣市→鄉鎮區）為什麼有一段 `if (filters.county !== county) return`？

那是**過期回應競態守衛**（`index.vue` 第 274–282 行）。`loadTownships(county)` 是 async，使用者快速切換縣市時，先發的請求可能後回來，把**舊縣市**的鄉鎮清單寫進去，造成選項與縣市不一致。`await` 回來後先檢查「現在的縣市還是不是當初那個」，不是就丟棄結果。任何 async 之後要回寫 UI 狀態的地方，都要想這件事。

### Q6. 改完 URL 同步後，重整網址帶的條件不見了？

檢查兩點：(1) 你的 filter key 有沒有在 `defaultFilters` 裡宣告——`useTemplateListPage` 初始化時**只接受 `defaultFilters` 既有的 key**（第 63–66 行），沒宣告的 key 不會從 URL 還原。(2) 排序的 URL glue（`index.vue` 第 311–333 行）是頁面層自己維護的，複製時別漏掉；還原必須在註冊 watch **之前**做（第 321–323 行），否則還原動作會被當成使用者操作反而清掉頁碼。

## 4. 後端接軌預告（`useFetch` 替換）

範本的資料層是「後端就緒」設計：對外 CRUD **全部非同步**（回 `Promise`），內部先用 module-level `ref` 單例當 mock store。未來後端 API 好了，**只改 `useVisitRecords.ts` 內部實作，頁面一行都不用動**（針對介面而非實作寫程式）。

每個函式旁邊都留了接縫註解（`useTemplateMembers.ts` 第 139–167 行），示意對應的 RESTful 端點：

```ts
export function useVisitRecords() {
  // 後端接軌：改為 useFetch('/api/visit-records')（GET 全量清單）— [SD 待定]
  const records = computed(() => store.value)

  // 後端接軌：改為 useFetch(`/api/visit-records/${id}`)（GET 單筆）— [SD 待定]
  async function getById(id: string): Promise<VisitRecord | undefined> {
    const found = store.value.find(r => r.id === id)
    return found ? cloneRecord(found) : undefined
  }

  // 後端接軌：改為 useFetch('/api/visit-records', { method: 'POST', body: input }) — [SD 待定]
  async function create(input: VisitRecordInput): Promise<VisitRecord> { /* … */ }

  // 後端接軌：PUT /api/visit-records/${id} — [SD 待定]
  async function update(id: string, input: VisitRecordInput): Promise<VisitRecord> { /* … */ }

  // 後端接軌：DELETE /api/visit-records/${id} — [SD 待定]
  async function remove(id: string): Promise<void> { /* … */ }

  return { records, getById, create, update, remove }
}
```

> **誠實原則**：後端 API contract（端點、欄位、錯誤格式、權限）尚未由 SD 定案前，一律標 `[SD 待定]`，**不要自己捏造 API 規格**。目前的非同步 mock 已足以讓前端完整運作與示範；等 SD 產出 API 規格後，把 `store.value.find(...)` 這類內部實作換成 `useFetch` 即可。
